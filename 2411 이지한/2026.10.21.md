# 캡스톤 일지

## 2026.10.21.

이번 기간에는 로그인 쪽을 서버와 앱에서 실제로 쓸 수 있는 수준까지 만드는 데 집중했다. 이메일 인증번호로 회원가입을 하고, 비밀번호를 잊어버렸을 때 인증번호로 재설정하는 흐름을 완성해서 앱과 연결했다. 그러는 사이 팀원이 만든 앱 코드를 받아 합치면서 서버와 앱이 서로 다르게 만든 부분을 찾아 맞췄고, 팀원이 조사해 온 AI 모델 보고서를 같이 검토했다.

### 일주일 동안 내가 만들어 낸 것

회원가입 때 이메일로 6자리 인증번호를 보내서 확인한 사람만 가입할 수 있게 만들었고, 이 흐름을 앱 화면과 연결했다. 비밀번호 찾기도 서버 API를 만들었다. 이메일로 인증번호를 받고, 인증이 끝나면 재설정용 토큰을 받아서 그 토큰으로 새 비밀번호를 정하는 순서다. 앱에서 가입과 비밀번호 찾기를 직접 눌러 보면서 실제 메일이 오는 것까지 확인했다. 비밀번호 찾기는 앱 팀이 아직 화면을 만드는 중이라서 명령어로 호출하는 방법과 화면 디자인 시안도 따로 만들어 전달했다. 문서도 고쳤다. 새로 생긴 API를 반영해서 API 명세서를 97개에서 100개로 늘렸고, 개발 요구사항 정의서를 v0.3으로 올렸다. 팀원이 조사한 근육 특징 AI 모델 보고서(EfficientNet-B0와 DINOv3 ViT-S/16)를 읽고 두 모델의 차이와 EC2에서 돌릴 때 필요한 사양을 따져 봤다. 팀원이 내 서버 코드를 읽고 주석을 달 수 있게, 읽기 쉬운 파일 두 개를 골라 안내하기도 했다.

### 일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법

가장 오래 걸린 건 인증 메일이 안 오는 문제였다. 원인이 한 가지가 아니었다. 첫째, 서버를 메일 설정 없이 실행해서 메일을 보내는 대신 로그에만 번호가 찍히는 개발 모드로 떠 있었다. 서버를 터미널에서 환경변수를 넣고 실행하도록 바꿨다. 둘째, 설정 파일에 적어 둔 한글이 깨져서 메일 제목이 이상하게 나왔다. 한글 기본값을 설정 파일이 아니라 자바 코드로 옮겨서 해결했다. 셋째, 서버는 정상인데도 메일이 스팸함으로 들어갔다. 서버 코드를 거치지 않고 파이썬으로 직접 보낸 테스트 메일도 스팸함으로 간 걸 보고, 새로 만든 계정에서 자동 메일을 반복해 보내서 생긴 문제라고 판단했다. 임시로 앱 안내 문구에 스팸함도 확인하라고 넣었고, 근본적으로는 전용 도메인으로 발송하는 서비스가 필요하다. 또 서버를 다시 켜면 메모리에 있던 인증번호가 사라져서 만료됐다는 오류가 났는데, 개발 중에는 서버를 켜 둔 채로 바로 입력하기로 했고 나중에 DB에 저장하는 방식으로 바꿀 수 있다. 팀원 앱 코드를 받아서 합쳤을 때는 비밀번호 찾기가 맞지 않았다. 팀원은 예전 명세서대로 메일 링크 방식으로 만들었는데 서버는 인증번호 방식으로 바뀐 상태였다. 방식이 바뀐 걸 앱 팀에 전달하지 못한 게 원인이라서, 앱 쪽 코드를 서버에 맞게 고치고 테스트로 확인했다.

### 내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점

문제가 생길 때마다 원인을 한 번에 단정하지 않고 하나씩 나눠서 확인한 건 잘한 것 같다. 서버 코드를 거치지 않고 메일만 따로 보내 보는 식으로 범위를 좁혔고, 이번에 겪은 문제 8가지를 문서로 정리해서 상태를 표시해 뒀다. 아쉬운 점은 소통이다. 인증 방식을 바꿨으면 명세서를 먼저 고치고 앱 팀에 알렸어야 했는데 그러지 못해서 서로 다른 방식으로 만들어졌다. 또 문제를 찾느라 로그를 그대로 붙여 넣는 과정에서 민감한 값이 같이 노출됐다. 앞으로는 값을 지우고 공유하고, 노출된 건 폐기해서 새 계정으로 바꾸려고 한다. 앱 테스트 14개가 실패하는 것도 확인했는데, 코드 문제가 아니라 팀원마다 Flutter 버전이 달라서 화면 비교 기준 이미지가 어긋나는 거였다. 이건 팀 전체가 같은 버전으로 맞춘 뒤에 기준 이미지를 한 번에 다시 만들어야 한다.

### 다음주까지 해올 것

프로젝트 이름이 MOVID로 바뀌었으니 메일 제목과 서버 문서에 남아 있는 예전 이름을 바꾸고, 메일 발송 계정도 새로 만들어 교체하려고 한다. 팀 Flutter 버전을 맞추자고 제안해서 앱 테스트의 기준 이미지를 정리할 것이다. 그리고 AI 모델 중 무엇을 쓸지, 어디서 돌릴지 팀원들과 결정해서 체형 분석 부분을 실제 모델과 연결할 준비를 한다.
