## 2026.09.02.

이번 주는 지난주에 산학기업에서 요청한 ERD 다이어그램이랑 API 명세서를 작성하는 데 집중했다. 기획서에 적어둔 주요 기능 8가지를 하나씩 뜯어보면서 어떤 데이터가 오가야 하는지 정리하고, 그걸 바탕으로 테이블 구조와 API 엔드포인트를 뽑아냈다.

### 일주일 동안 내가 만들어 낸 것
ERD 다이어그램을 draw.io 로 그렸다. 사용자, 체형 기록, 목표 사진, 분석 결과, 부위별 발달도, 운동 루틴 이렇게 6개 테이블로 나누고, 사용자 한 명이 여러 번 체형 기록을 남길 수 있게 설계했다. 분석 결과는 MediaPipe Pose(ERD 뽑아주는 생성형 ai)에서 뽑아낸 키포인트 좌표를 그대로 저장하기보다, 부위별 점수로 가공해서 저장하는 구조로 잡았다.
또한 뽑은 api 명세서를 바탕으로 ERD를 다시 보수했다.

### 일주일 동안 겪었던 힘든 점, 극복했다면 해결 방법
제일 걸렸던 건 분석 결과를 어떤 단위로 쪼개서 저장할지였다. 처음에는 MediaPipe가 뽑아주는 keypoint 좌표를 그대로 저장하려고 했는데, 그러면 나중에 프론트에서 읽기 힘들고 가독성이 떨어질 것 같아서 직적 그리는 방법으로 변경했다. 그리고 로그인 관련 API를 처음 설계할 때 아예 빼먹고 있었다는 걸 팀원이 지적해줘서 뒤늦게 추가하는 일도 있었다.

### 내가 잘한 것과 더 잘할 수 있었는데 아쉬웠던 점
테이블을 기능 단위로 먼저 나눠 생각한 다음에 관계를 정한 게 잘한 것 같다. 아쉬운 점은 처음 해보는거라 미숙해서 실수를 많이했다.

### 다음주까지 해올 것
Flutter 프로젝트랑 Spring Boot 프로젝트 초기 환경세팅을 하고, ERD를 실제 MySQL 스키마로 옮겨서 반영할 거다. 그리고 에러 응답 형식을 통일해서 API 명세서를 한 번 더 정리하고, 팀원들이랑 개발 환경도 맞춰볼 예정이다.
